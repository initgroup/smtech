# RMS-PUB-20261008-01 · 퍼블리싱 협업 구조 개편

날짜: 2026-10-08. 비교 기준은 개편 직전 소스 다운로드 ZIP의 manifest입니다.

## 변경 이유

화면 문자열·시연 저장소·이벤트가 큰 JS 파일에 섞여 있어 외부 UI 변경을 내부 JSP/백엔드 수정본에 이식하기 어려웠습니다. 편집 책임을 분리하고 다음 전달부터 파일별 변경분을 검토할 수 있도록 개편했습니다.

## 변경 내용

| 영역 | 변경 및 이식 영향 |
|---|---|
| HTML | 198개 templates/ 파일로 화면·폼·팝업·수신 리포트 마크업 분리. 정적 템플릿 컴파일과 색인 생성 |
| CSS | 기존 운영 CSS 유지. 디자인 토큰 분리, 신규 CSS 가독성 정리. 드래그 수치만 CSS 변수로 전달 |
| 공용 JS | template/component/DOM/layer/command runner 재사용. SFR 레이어를 ui 모듈로 이동 |
| 데이터 | 공용 selector, 게시판 JSON, XML parser/repository, 시연 store/adapter 분리 |
| 서버 연결 | 주입 가능한 HTTP adapter, 21개 명령 계약, 응답 schema/예제. 비동기 성공 이후 UI 갱신·실패 보존·중복 쓰기 방지 |
| JSP | c:out/c:forEach 목록·상세 JSP, 서버 HTML 상세 레이어 JS, 자산 로드 예제 |
| 소스 전달 | 소유권 규칙, 이전/이후 해시, 변경 파일 ZIP, 삭제 목록, 텍스트 diff, 읽기 전용 대상 충돌 검토 |
| 도구 | 단일 build.cjs, 생성물 검사, 전체 ZIP의 Git 없는 재생성 지원 |

## 기존 기능 유지

메인 1·2의 공고 박스/목록, 통합검색, 공개 4개 게시판 각 5건·상세 레이어·더보기, 접힌 시연 도구, 15개 SFR 표시·관련 강조·전체 안내·개별/전체 펼침, SFR 바를 가리지 않는 레이어, XML 4묶음·25문서 리포트와 신청 단계, 역할·JSON 백업·파일 시연 기능을 유지합니다. 메인 2 배너·자주 찾는 서비스는 추가하지 않았습니다.

## 첫 이식 시 주의할 변경점

JS 로드 경로가 변경되었습니다. [file-map.json](file-map.json)과 asset-manifest.json을 함께 보고 기존 JSP 스크립트 include를 병합하세요. 구 버전 core.js/board-data.js/mydata-report.js/views.js는 제거 대상이며 새 파일들과 혼용하지 않습니다. 내부 app.js 수정 내용은 integration 소유 어댑터로 옮긴 뒤 새 UI controller를 반영합니다.

contracts와 공통 골격은 공동 검토 대상입니다. 이번 개편은 DOM id/name/data-action의 기존 연결과 데이터 백업 v1을 유지합니다. 생성물과 원본을 서로 다른 버전으로 전달하지 않습니다.

## 검증 범위

기존 업무·백업·공고·XML·DOM 검사, 새 어댑터의 비동기 성공/실패·중복 호출·multipart 경계, 모듈 분리와 템플릿 빌드 일치, 변경분 ZIP의 충돌·삭제·경로 보호, 전체 소스 ZIP의 해시·재현성·다운로드를 검사합니다. 최종 결과는 [검증 문서](../../docs/05-validation.md)를 참고하세요.

운영 Java/JSP 컨테이너·인증·공공 API·DB 연결은 제공되지 않아 실제 서버 통합 검사 대상에 포함되지 않습니다. 브라우저 DOM 동작 검사는 화면 렌더링 엔진의 픽셀 비교 검사를 대신하지 않습니다.

파일 해시의 납품·Windows 체크아웃 간 일치를 위해 .gitattributes에 편집 원본 LF 정책과 원본 자료 바이트 보존 예외를 추가했습니다. 내부 저장소에서는 공동 검토 후 적용합니다.
