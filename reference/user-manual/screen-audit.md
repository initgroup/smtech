- 흰색 바탕, 파란 RMS 로고, 작은 검정 본문 글씨, 가늘고 옅은 회색 테두리의 밀집된 업무 화면이다.
- 내부 홈은 넓은 청색/남색 RMS 배너 아래 신청공고 표와 접수 중 공고 카드를 배치한다(p.20).
- 목록 화면은 좌측 제목과 우측 breadcrumb, 옅은 회색 검색영역, 본문 그리드 순서다. 검색 버튼은 오른쪽의 진한 파랑이다(pp.33/43/45/69/75/76).
- 목록 그리드는 보라회색 헤더와 흰 글씨, 가는 세로/가로 셀 경계, 옅은 교차 행 배경, 큰 빈 영역, 가로/세로 스크롤을 갖는다. 테이블 하위 숫자·금액·날짜가 밀집되어 있다.
- 상세 폼은 옅은 회색 라벨 셀과 흰 값 셀로 구성한 테이블이다. 2열 라벨/값 쌍을 한 행에 넣고 긴 내용은 행을 합친다(pp.23/25/70).
- 모달은 어두운 회색 헤더, 흰 제목, 오른쪽 X, 흰 본문과 배경 딤 처리다. 긴 내용은 모달/페이지 안에서 스크롤된다(pp.21/28/35/53/71/77).
- 주 행동(검색·제출·등록·추가)은 파랑, 임시저장/수정은 대체로 녹색, 삭제/회수는 빨강, 닫기/찾아보기는 짙은 회색, 목록/일부 보기 버튼은 파란 테두리다. p.61 등에서 임시저장도 파란색인 사례가 있어 역할별 컬러가 완전히 일관적이지 않다.
- 협약 변경은 변경항목 체크/라디오 스타일 선택에 따라 아래 '변경상세'의 탭형 제목과 입력 내용이 바뀐다(pp.53-57/61-65). 이를 전역 탭 탐색 구조로 확대 해석하면 안 된다.
- 정확한 색상 코드·폰트·간격·DOM 클래스는 PNG만으로 확정할 수 없다. 공개 CSS와 JS의 실측값으로 최종 반영한다.

공급기관(pp.27-30): 추가 버튼 -> 기관명 또는 사업자번호 검색 모달 -> 기관 선택/추가 -> 확인. 목록에는 공급기관명, 설립일, 사업자등록번호, 대표자명, 법인번호, 대표전화번호, 주소, 담당자명, 담당자전화번호, 지원금, 관리 버튼이 보인다. 검색되지 않는 기관은 SMTECH 기관정보 가입이 필요하다고 설명한다(p.28).

승인성 변경(pp.53-57): 공고/기업/프로그램 요약, 신청자명, 연락처, 변경항목, 변경 전/후 내용, 변경사유, 첨부서류, 변경상세, 임시저장·변경신청·닫기. 변경항목은 사업목표, 정부지원금, 지원기간, 지원금사용계획, 공급기관이다. 해당 항목에 따라 텍스트·금액·기간·기관 목록 입력이 바뀐다. 신청 후 담당자 승인까지 진행중/변경요청이고 승인되면 변경승인이다(pp.59/67).

통보성 변경(pp.61-65): 기업명, 대표자명, 총괄책임자, 실무담당자, 기타. 전후 비교 및 사유·첨부를 공통 제공한다. 총괄/실무담당자 변경은 성명·유선전화·휴대전화·이메일 전후 값을 갖는다. 통보성은 단순 통보로 바로 변경승인된다고 명시한다(p.67).

변경현황(p.67): 연도/지역/과제번호/공고번호/공고명/신청일/변경구분/변경상태 검색과 엑셀다운로드. 변경상태, 승인관리 보기, 변경구분, 변경항목, 공고 등의 목록. 승인 상세에는 신청사유와 승인사유/승인사유 첨부 및 전후 변경값을 보인다(p.68).

### 소통관리 (pp.76-77)

소통관리 목록(p.76): 제목, 등록자, 처리여부, 등록일자 검색, 글쓰기 버튼. 목록은 순번, 비밀글, 제목, 첨부파일, 답글수, 등록자, 등록일시, 처리여부, 처리일시, 관리 열이다. 공지사항과 오류문의가 한 목록에서 보인다.

게시물 등록 모달(p.77): 제목, 등록자, 과제번호, 공고번호, 기업명, 사업자번호, 연락처, 비밀글여부, 게시내용, 첨부파일 목록, 저장/닫기. 내용 편집기는 굵게/기울임·목록·표·이미지·링크·코드 등의 도구와 Markdown/WYSIWYG 모드 선택이 보인다. 정확한 편집기 제품은 실소스 확인 대상이다.

화면 placeholder에는 과제번호는 S로 시작하는 8자리, 공고번호는 뒤 숫자 4자리 입력 안내가 보인다. 설명문에는 이름·소속·연락처·과제번호·공고번호·문제사항을 정확히 기재하라고 안내한다. p.77 상단의 주관기관 필수입력 안내가 기업용 매뉴얼에 함께 캡처되어 있으므로 필수조건은 사용자 권한별 확인이 필요하다.

## 프로토타입 반영 제안

1. 공개된 기존 CSS/JS를 보존하고, 상단 수평 메뉴·검색영역·그리드·테이블 폼·모달 흐름을 유지한다. 신규 화면과 보강 요소에는 독립 접두어를 적용한다.
2. 공고/신청/첨부 데이터를 분리한다. 신청서류 정의는 공고마다 필수/선택/허용파일정책을 가질 수 있고, 제출 파일은 해당 서류 ID와 연결한다.
3. 결과보고는 프로그램 ID -> 보고서 그룹 -> 복수 첨부의 구조다. 신청 서류의 단일 파일 정책과 공통 컴포넌트를 무리하게 동일화하지 않는다.
4. 임시저장/제출/회수/변경요청/승인/결과보고 제출완료 상태를 예시 JSON으로 시연하고, 제출 이후 수정 가능 여부를 화면에 일치시킨다.
5. 금액은 저장 단위를 명시하고 모든 입력·목록에 단위를 표시한다. 기존 문서의 원/천원 불일치를 고객 확인 항목으로 남긴다.
6. 기술닥터 등 신규 업무는 RFP와 운영매뉴얼에서 요구사항을 별도로 확인한다. 이 기업용 PDF로 뒷받침되지 않는 기능은 신규 제안/추정임을 표시한다.
