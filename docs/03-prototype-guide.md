# 화면·데이터 설계와 시연 가이드

## 화면 구성

실행: `python tools/serve.py` → `http://127.0.0.1:8080/region/rms/`

| 주소의 # 이후 | 화면 | 권장 역할 |
|---|---|---|
| `home` | 사업공고, 로그인 패널, FAQ, 최근 질문 | 로그인 전/지원기업 |
| `doctors` | 기술닥터 통합검색·비교 | 지원기업/TP |
| `doctor/D001` | 상세정보·변경이력·매칭 요청 | 지원기업/등록기관 |
| `matches` | 매칭 요청·지원진행·실적 등록 | 지원기업/TP |
| `stats` | 지역·기술·산업·기간 통계, CSV | TP/관리자 |
| `documents/A001` | 사업신청 접수서류·동의·제출·보완 | 지원기업/TP |
| `faq` | FAQ 유형·내용 검색, 관련 질문 | 모든 역할 |
| `questions` | 공개 질문·답변 목록/상세 | 모든 역할 |
| `manage` | 산업·기술·상담·기관·지역·선정사유·업무분류 | 관리자 |
| `manage/home` | 메인 배치·노출, 업무분류 매핑, 공개 질문 노출 | 관리자 |
| `manage/documents` | 9종 연계대상 관리·대상 추가 | 관리자 |
| `guide` | 고객 시연 안내·초기화 | 모든 역할 |

상단 역할 선택은 실제 인증과 무관한 시연 도구다. 관리자 역할의 메뉴는 실제 권한으로 간주하지 않는다. 화면 사이 이동은 로컬 hash 경로이며 운영 `.do` 라우트를 대체하는 제안이 아니다.

## 시연 1: 전문가 검색 → 지역 간 매칭 → 지원실적

1. 역할을 **지원기업**으로 선택한다.
2. **기술닥터**에서 지원가능 지역 ‘충남’, 기관유형 ‘연구기관’, 기술분야 ‘소재분석’ 등을 조합해 검색한다.
3. 초기화 후 김가람·이서준 두 명의 비교 체크박스를 선택하고 **선택 비교**를 누른다.
4. 이서준 상세에서 대전 등록/충남 지원가능을 확인한다.
5. **매칭 요청**에 ‘정밀가공 부품의 표면 결함 원인 분석’을 입력한다.
6. **관리기관 · 충남TP** 역할로 바꿔 **매칭·지원 관리 → 지원 시작 → 실적 등록**을 진행한다.
7. **통계·성과**에서 지역·기간을 바꾸고 CSV를 내려받는다.

매칭 상태는 `요청접수 → 지원진행 → 지원완료`이다. 동일 기업/전문가의 미완료 중복요청을 막는다. 상태/승인기관은 검토를 위한 가정이며 실제 업무 확정이 필요하다.

## 시연 2: 등록정보 현행화와 기관권한

1. **충남TP** 역할에서 김가람(D001) 상세를 연다.
2. **등록정보 수정**에서 취득기술/경력을 변경하고 저장한다.
3. 상세 하단에서 변경일시·담당자·변경 전후 값이 추가된 것을 확인한다.
4. 대전 등록 이서준(D002) 상세에는 수정 버튼이 없음을 확인한다.
5. **기술닥터 등록**에서 가상 사용자 ‘윤새결’을 선택하고 분류·지역을 입력한다.
6. 같은 가상 사용자를 다시 등록하면 중복등록 오류가 표시된다.

정보 현행화 기준은 시연 기준일 2026-09-08에서 12개월이다. 운영에서는 서버 시간과 발주기관이 정한 주기를 사용한다.

## 시연 3: 동의 → 조회 → 불일치·실패 처리 → 제출

1. **지원기업 → 사업신청·관리**에서 가상 한빛정밀/지역기업 성장사다리(A001)를 연다.
2. 동의 전 **필수서류 일괄조회**를 누르면 동의 안내가 나온다.
3. 정보제공 동의를 체크하고 다시 일괄조회한다.
4. 사업자등록증명은 `보완필요`, 지방세는 `조회실패`, 나머지 필수서류는 `조회완료`로 바뀐다.
5. 사업자등록증명 **상세**에서 신청서 주소 99와 조회된 주소 100을 비교한다. 기존 입력은 아직 바뀌지 않는다.
6. **조회 주소 반영**을 선택하면 주소가 바뀌고 이력이 남는다. **기존 입력값 유지**를 선택한 경우 파일로 보완해야 한다.
7. 지방세 **재조회**는 가상 성공으로 바뀐다.
8. 필수서류 상태를 확인하고 **신청서 제출 → 가상 신청서 제출**한다.
9. 제출 후 수정은 잠긴다. 실제 RMS로 전송되지 않는다.

다른 사업 A002의 4대 보험 서류는 항상 ‘정보 미제공’ 사례로 재현된다. **상세 → 파일 선택 → 파일 제출 시연**으로 대체한다. 파일은 1개/10MB 이하, PDF·HWP·HWPX·JPG·PNG·ZIP을 허용하는 시연 규칙이다. PDF p26의 단일첨부는 근거가 있으나 10MB 등 상세 제한은 운영 정책 확인 전 가정이다.

## 시연 4: 관리기관 보완요청 → 기업 재제출

1. **충남TP** 역할에서 A001 신청서를 선택한다.
2. 국세 또는 사업자등록증명의 **보완요청**에 ‘최신 발급일 기준 서류로 보완해 주세요’를 입력한다.
3. 상태가 `보완필요`, 신청서가 `작성중`으로 바뀐다.
4. **지원기업** 역할에서 사유와 처리이력을 확인한다.
5. 재조회 또는 파일 제출 후 다시 신청서를 제출한다.

과거 주소 확인만으로 기관의 새 보완요청을 끝낼 수 없도록 분리했다. 운영에서는 보완 요구사항별 처리 방식(재조회 가능/수동 증빙 필요)을 더 세분화한다.

## 시연 5: 메인·소통 구성

1. 메인 FAQ에서 ‘암호’ 또는 ‘파일’을 검색한다. 키워드와 답변을 검색한다.
2. 업무유형과 검색어를 조합한다. 정확한 부분일치가 없으면 글자/키워드 유사도를 기준으로 관련 질문을 제안한다. AI 검색은 아니다.
3. **관리자 → 설정 → 메인·소통 설정**에서 FAQ를 위로 이동한다.
4. 공개 질문 하나의 메인 노출을 해제한다. 메인에서는 사라지고 전체 소통 목록에는 남는다.
5. 비공개 글의 노출 체크박스는 선택할 수 없다.
6. **표준분류 → 소통 업무유형**에서 사용/노출을 해제하면 해당 유형의 공개 조회가 제한된다.
7. 기존 업무분류 매핑으로 FAQ와 질문의 분류 변경을 함께 확인한다.

## 시연 6: JSON 저장·복원

1. 기술닥터 정보 수정이나 보완요청을 수행한다.
2. 상단 **JSON 저장**으로 상태 파일을 내려받는다.
3. **시연 안내 → 가상 초기자료로 되돌리기**로 초기화한다.
4. **JSON 불러오기 → 파일 선택 → 불러오기**로 상태를 복원한다.
5. 페이지를 다시 열어도 같은 브라우저/주소에서 상태가 유지되는지 확인한다.

실제 디스크 JSON을 서버가 자동 수정하지 않는다. 브라우저 `localStorage`의 상태를 사용자가 내보내고 가져오는 방식이다. 파일 크기/형식/분류 참조/상태를 검증하고, 저장 실패 시 이전 상태를 유지한다. 첨부파일 내용은 JSON에 들어가지 않는다.

## 데이터 모델

`data/seed.json`의 루트 `schemaVersion: 1`을 기준으로 한다.

| 컬렉션 | 역할 | 운영 DB 연결 후보 |
|---|---|---|
| users | 가상 SMTECH 사용자 | 실제 SMTECH 사용자 연계 |
| doctors | 전문가 정보·등록기관·복수 분류·변경이력 | 전문가, 경력/학위/기술/자격/포상, 지역 연결 테이블 |
| classifications | 종류·상위분류·사용·노출 | 공통 표준분류, 기존 코드 매핑 |
| matches | 기업·전문가 요청/상태/결과 | 매칭 요청·지원 활동·성과 |
| programs | 가상 사업과 필수서류 ID | 기존 과제/공고/요건과 연결 |
| applications | 신청기업, 사업, 주소, 동의, 제출상태 | 기존 접수 ID·기업·사업 관계 |
| applications[].docs | 서류별 상태·조회시각·파일 메타·처리이력 | 동의/조회요청/응답/증빙/보완 이력 |
| documentTypes | 증빙유형·기관 표시·사용 | 제공기관 코드/연계 스키마/유효기간 |
| faqs / questions | 업무유형·키워드·공개/노출 | 기존 FAQ·소통 게시물과 연결 |
| settings | 메인 배치·노출·현행화 주기 | 기관별 설정 저장소 |
| audit | 시연 조작 요약 로그 | 서버의 감사로그로 대체 |

실제 물리 테이블명·PK·API 엔드포인트로 확정한 모델은 아니다. 실제 사용자·권한은 클라이언트 JSON 값을 신뢰하지 않고 서버 세션으로 판정해야 한다.
# 사업신청 단계 이동

서류제출현황의 01~04 단계 버튼과 이전·다음 버튼으로 이동합니다. URL은 `#documents/신청서ID/단계번호`이며 기존 `#documents` 주소는 03 접수서류 확인을 엽니다.

- 01 사업 선택: 사업 상세, 기존 신청서 열기, 지원기업의 신규 신청을 제공합니다.
- 02 신청기업 정보: 기업명·대표자·신청서 주소를 저장합니다. 단계 버튼 이동 시에도 저장하며, 주소 변경 시 기존 주소 증빙을 보완필요로 전환합니다.
- 03 접수서류 확인: 동의, 조회, 파일 제출, 서류 상세 및 기관 보완요청을 처리합니다.
- 04 제출 및 보완: 필수서류 준비 여부와 보완 사유를 확인하고 제출·보완·재제출합니다.

관리기관은 기업정보를 조회만 할 수 있습니다. 제출완료 신청서는 모든 단계를 조회할 수 있지만 보완요청 전까지 수정할 수 없습니다. 기업정보를 입력한 후 브라우저 뒤로가기나 다른 상위 메뉴를 이용하려면 먼저 기업정보 저장을 누르세요.
