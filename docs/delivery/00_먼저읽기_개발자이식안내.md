# RMS 내부 개발자 이식 안내

이 ZIP은 내부 이식용 **업무 화면 소스**입니다. 먼저 이 문서, 01_배포내역.md, 02_파일경로와변경분적용.md 순서로 읽어 주세요. 현재 버전과 파일별 SHA-256은 release-manifest.json에 있습니다. 과거 변경내역은 01_배포내역.md와 release-history.json에 누적됩니다.

## 적용할 경로

| ZIP 경로 | 용도 | 적용 방법 |
|---|---|---|
| web/index.html | 업무 화면의 전체 HTML 뼈대 | 내부 공통 JSP 레이아웃에 수동 병합 |
| web/templates/ | 편집 가능한 업무 HTML 조각 | 구조·레이어·접근성 수정 원본 |
| web/static/css/rms-*.css | 업무 화면 디자인·반응형 배치 | CSS 변경만으로 화면 배치 조정 |
| web/static/js/rms-enhance/common/ | 템플릿·컴포넌트·폼·레이어·저장 명령 공용 함수 | 공통 재사용 |
| web/static/js/rms-enhance/presenters/ | DTO를 화면 템플릿에 연결 | DB 조회·저장 코드를 넣지 않음 |
| web/static/js/rms-enhance/data/ | 조회 선택자·게시판·XML DTO 처리 | 서버 DTO를 UI용 구조로 변환 |
| web/static/js/rms-enhance/adapters/http.js | 서버 요청과 응답 검증 | 내부 서비스 계약과 연결 |
| web/integration/config.js | 서버 URL·인증·CSRF 연결 | **내부 개발자 소유. 후속 ZIP으로 덮어쓰지 않음** |
| web/contracts/ | 명령 목록·스냅샷 스키마 | 양측 합의 후 변경; example은 가상 DTO 참고 |
| examples/jsp/ | JSTL 목록·상세·공용 자산 예시 | 실제 컨트롤러/DTO에 맞춰 이식; 자동 배포 대상 아님 |
| examples/integration/ | 서버 어댑터 연결 예시 | 내부 전용 파일로 복사한 뒤 수정 |
| tools/ | 템플릿 컴파일·변경분 비교 도구 | 개발 작업용; 웹 서버 배포 대상 아님 |

**웹 서버에는 web/의 필요한 업무 파일만 적용합니다.** docs/, examples/, tools/, 루트의 이력·manifest 파일은 개발 참고 자료입니다. web/contracts/snapshot.example.json은 가상 응답 예시이며 실제 서비스 응답으로 사용하지 않습니다.

## 시연 도구와 업무 화면의 분리

퍼블리셔 작업 폴더의 prototype/region/rms/index.html은 검토용 시연 진입점입니다. 그 화면 상단의 기능개선 시연도구와 SFR 안내는 prototype/region/rms/demo/ 아래 HTML·CSS·JS·데이터에서 조립됩니다. 개발자 ZIP의 web/index.html은 별도의 application.html에서 가져온 업무 화면입니다.

시연 상위 박스를 CSS로 숨겨서 전달하는 방식이 아닙니다. 이 ZIP에는 **시연 도구, 배포내역 팝업, SFR 번호 박스/설명 레이어/시연 안내 페이지, 역할 시뮬레이터, JSON 백업·복원, 가상 저장소, 4개 XML 샘플 원본 파일이 들어 있지 않습니다.** XML 파서와 실제 수신 DTO를 표시하는 업무 리포트 기능은 들어 있습니다. 서버의 receipts 배열을 연결해서 사용합니다.

구형 v1.0.0 전체 ZIP을 받았던 경우에는 그 안의 index.html과 static 전체를 덮어쓰지 마세요. 이번 구조를 신규 기준으로 잡고 업무 화면만 병합하세요. 특히 구형 generated/requirements.js, ui/sfr-layer.js, data/demo-store.js, adapters/demo.js와 SFR CSS는 운영 JSP에 연결하지 않습니다.

## 최초 이식 순서

1. ZIP을 별도 검토 폴더에 풀고 release-manifest.json의 파일 목록과 버전을 보관합니다.
2. web/index.html의 header/main/footer, dialog/toast host, CSS·JS 로드 순서를 내부 공통 JSP에 맞게 병합합니다. id, name, data-action은 화면 이벤트 계약이므로 임의로 삭제하지 않습니다. examples/jsp/를 참고합니다.
3. web/integration/config.js를 내부 전용 경로로 복사해 API URL·CSRF·인증·오류 변환을 구현하고 공용 app.js보다 먼저 로드합니다. 기본 /rms/api/bootstrap은 연결 예시입니다. 실제 서버가 없으면 업무 진입점에는 연결 오류가 표시됩니다.
4. docs/07-data-contract.md, web/contracts/commands.json과 snapshot.schema.json을 기준으로 컨트롤러/서비스/DTO를 연결합니다. bootstrap과 성공한 쓰기 명령은 contractVersion/state/session/receipts/result 스냅샷을 반환합니다. 실제 DB 모델은 내부 매퍼에서 변환합니다.
5. 권한·소유기관·마감·제출잠금·파일검증은 서버에서 처리합니다. 가상 응답 예시를 운영 초기 데이터로 로딩하지 않습니다.
6. CSS는 rms-tokens → rms-shell → rms-enhance → rms-home-refresh → rms-mydata-report의 역할을 참고하고, 실제 로드 순서는 web/asset-manifest.json을 유지합니다. 원본 ui.css/uiCustom.css·폰트·이미지는 보존했습니다.
7. 템플릿 수정 후 ZIP 루트에서 node tools/compile_templates.cjs를 실행합니다. web/templates가 원본이고 generated/templates.js는 재생성 산출물입니다. JSP 서버 렌더링으로 옮기는 경우에는 templates를 참고해 c:out 등으로 출력 값을 이스케이프합니다.
8. 메인 두 시안, 공개 게시판/검색, 로그인 권한, 저장 성공·실패 시 입력 보존, 신청 단계, 파일 제출, XML 수신 리포트, 모바일 레이아웃을 확인합니다.

## 이후 변경분 이식

전체 덮어쓰기를 하지 않습니다. 이전 ZIP을 기준으로 새 ZIP과 파일별 해시를 비교하고, 내부 파일이 이전 버전과 같은 파일만 변경 후보로 봅니다. 내부에서 수정한 파일과 JSP·계약 파일은 수동 병합합니다. tools/delivery_delta.py는 변경분 ZIP과 읽기 전용 충돌 비교 결과를 만들며 내부 소스를 자동으로 수정하거나 삭제하지 않습니다. 자세한 명령은 02_파일경로와변경분적용.md에 있습니다.

파일 상단 @owner/@since/@change는 주요 구조 변경의 단서입니다. 버전별 변경 경로와 해시 목록은 release-history.json 및 release-manifest.json을 기준으로 확인하세요. 내부 개발자는 별도 브랜치와 내부 변경이력을 유지하는 것을 권장합니다.
