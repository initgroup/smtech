## 변경분 ZIP 생성과 사전 비교

Python 표준 라이브러리만 사용합니다. 이전과 현재의 rms-developer-vX.Y.Z.zip을 보관하세요. 비교 도구는 ZIP 루트 tools/에 있습니다.

~~~powershell
python tools/delivery_delta.py --baseline 이전.zip --current 현재.zip --output 변경분.zip
python tools/delivery_delta.py --review 변경분.zip --target D:\검토폴더 --report 비교결과.json
~~~

--target은 ZIP을 별도 검토 폴더에 풀어 둔 루트입니다. 그 아래에 web/이 있어야 합니다. 내부 JSP 경로가 다르면 먼저 경로 대응표를 작성해 해당 파일을 비교하세요. 보고서는 target 밖에 저장해야 합니다. 이 도구는 적용·삭제 기능을 제공하지 않습니다.

변경분 ZIP에는 추가/수정 파일, 삭제 지시 목록, 이전·현재 해시와 텍스트 diff가 있습니다. web/integration/은 변경분에서 항상 제외합니다. web/index.html과 web/contracts/는 내부 파일의 해시가 같더라도 수동 검토 대상으로 표시합니다. 파일 삭제도 개발자가 참조 관계와 내부 변경 여부를 확인한 후 수행합니다.

| 비교 상태 | 의미 | 처리 |
|---|---|---|
| already-current | 이미 새 버전과 동일 | 유지 |
| ready-for-review | 내부 파일이 이전 배포와 동일 | 검토 후 변경분 적용 |
| conflict-local-modification | 내부 수정과 퍼블리셔 변경이 겹침 | 수동 병합 |
| missing-local-file | 내부 파일 없음 | 추가/누락 여부 검토 |

v1.0.0은 시연을 포함한 구형 전체 프로젝트 ZIP이므로 새 변경분 도구의 기준 ZIP으로 사용할 수 없습니다. v1.1.0을 최초 업무용 기준으로 보관하세요. 구형→이번 버전의 이동은 위 대응표와 00 안내를 보고 수동으로 진행합니다.

## 배포 버전 운영

퍼블리셔는 수정 완료 후 빌드·검증을 마치고 tools/package_source.py를 실행합니다. 변경된 소스에는 직전 버전의 patch 번호가 자동 증가하고, 같은 소스 재생성은 같은 버전과 같은 ZIP을 유지합니다. 별도 major/minor 배포는 --version X.Y.Z로 지정할 수 있습니다. 이미 보관된 버전 ZIP과 다른 내용으로 재사용하려 하면 중단합니다.

배포 전에 releases/next.json에 제목·변경내용·이식 주의사항을 작성합니다. 누적 기록은 releases/history.json과 RELEASES.md, 버전별 기록은 releases/records/vX.Y.Z.json, 버전 ZIP은 downloads/releases/에 보존합니다. 시연 도구의 배포내역 레이어는 이 누적 기록에서 생성됩니다. 다운로드의 smtech-source.zip은 최신 업무용 ZIP의 별칭입니다.
