## 변경분 ZIP 생성과 사전 비교

Python 표준 라이브러리만 사용합니다. 이전과 현재의 rms-developer-vX.Y.Z.zip을 보관하세요. 비교 도구는 ZIP 루트 tools/에 있습니다.

~~~powershell
python tools/delivery_delta.py --baseline 이전.zip --current 현재.zip --output 변경분.zip
python tools/delivery_delta.py --review 변경분.zip --target D:\검토폴더 --report 비교결과.json
~~~

--target은 ZIP을 별도 검토 폴더에 풀어 둔 루트입니다. 그 아래에 web/이 있어야 합니다. 내부 JSP 경로가 다르면 먼저 경로 대응표를 작성해 해당 파일을 비교하세요. 보고서는 target 밖에 저장해야 합니다. 이 도구는 적용·삭제 기능을 제공하지 않습니다.

변경분 ZIP에는 추가/수정 파일, 삭제 지시 목록, 이전·현재 해시와 텍스트 diff가 있습니다. web/integration/은 변경분에서 항상 제외합니다. web/index.html과 web/contracts/는 내부 파일의 해시가 같더라도 수동 검토 대상으로 표시합니다. 파일 삭제도 개발자가 참조 관계와 내부 변경 여부를 확인한 후 수행합니다.

| 비교 상태 | 의미 | 처리 |
|---|---|---|
| already-current | 이미 새 버전과 동일 | 유지 |
| ready-for-review | 내부 파일이 이전 배포와 동일 | 검토 후 변경분 적용 |
| conflict-local-modification | 내부 수정과 퍼블리셔 변경이 겹침 | 수동 병합 |
| missing-local-file | 내부 파일 없음 | 추가/누락 여부 검토 |

v1.0.0은 시연을 포함한 구형 전체 프로젝트 ZIP이므로 새 변경분 도구의 기준 ZIP으로 사용할 수 없습니다. v1.1.0을 최초 업무용 기준으로 보관하세요. 구형→이번 버전의 이동은 위 대응표와 00 안내를 보고 수동으로 진행합니다.

## 배포 버전 운영

퍼블리셔는 수정 완료 후 빌드·검증을 마치고 tools/package_source.py를 실행합니다. 변경된 소스에는 직전 버전의 patch 번호가 자동 증가하고, 같은 소스 재생성은 같은 버전과 같은 ZIP을 유지합니다. 별도 major/minor 배포는 --version X.Y.Z로 지정할 수 있습니다. 이미 보관된 버전 ZIP과 다른 내용으로 재사용하려 하면 중단합니다.

배포 전에 releases/next.json에 제목·변경내용·이식 주의사항을 작성합니다. 누적 기록은 releases/history.json과 RELEASES.md, 버전별 기록은 releases/records/vX.Y.Z.json, 버전 ZIP은 downloads/releases/에 보존합니다. 시연 도구의 배포내역 레이어는 이 누적 기록에서 생성됩니다. 다운로드의 smtech-source-design1.zip, smtech-source-design2.zip, smtech-source-design3.zip은 각각 최신 시안별 업무용 ZIP입니다. 각 ZIP에는 해당 CSS가 미리 적용되며 상단 시안 선택 도구는 포함하지 않습니다. 버전별 -design1·2·3.zip과 SHA-256도 보관합니다. smtech-source.zip은 시안 1과 같은 기본 디자인을 적용한 공통 ZIP 별칭입니다.

## 디자인 시안 선택: CSS 파일 하나 교체

이번 버전의 공통 HTML·JS를 처음 이식할 때는 web/index.html, web/templates/, web/static/를 함께 반영합니다. integration/의 내부 인증·API 코드는 유지합니다. 이 공통 구조를 한 번 적용한 뒤에는 HTML·JS·서버 코드를 수정하지 않고 디자인을 선택할 수 있습니다.

업무용 HTML은 static/css/rms-selected-design.css 하나를 공통 스타일 뒤에 불러옵니다. 시안별 ZIP을 받으면 해당 시안이 이미 적용되어 있어 추가 교체 없이 이식할 수 있습니다. 공통 smtech-source.zip의 기본값은 시안 1입니다. 이후 디자인을 바꾸려면 아래 파일 중 원하는 시안의 **전체 내용**으로 rms-selected-design.css를 교체하세요.

| 선택 | ZIP 안의 교체용 CSS | 배치·스타일 |
|---|---|---|
| 시안 1 | web/static/css/themes/rms-design1.css | 청색 목록형, 우측 업무 패널, 사각 버튼·블릿 |
| 시안 2 | web/static/css/themes/rms-design2.css | 청록 작업공간형, 좌측 업무 레일, 둥근 카드·버튼 |
| 시안 3 | web/static/css/themes/rms-design3.css | 남색 대시보드형, 업무 지표·번호 타일, 공고·게시판 분할 |

ZIP을 푼 폴더에서 시안 2를 선택하는 예시입니다.

~~~powershell
Copy-Item -LiteralPath './web/static/css/themes/rms-design2.css' -Destination './web/static/css/rms-selected-design.css' -Force
~~~

시안 1·3은 파일명의 숫자만 바꾸면 됩니다. 서비스에는 교체한 rms-selected-design.css만 배포하고 CSS 캐시를 갱신합니다. CSS link 경로, body 클래스, 페이지 경로, JSP/HTML, JavaScript를 추가로 바꿀 필요가 없습니다. 색상·아이콘 프레임·블릿·버튼·팝업·반응형 배치가 함께 적용됩니다.

시안별 콘텐츠는 같은 HTML에서 렌더링합니다. 업무 지표의 표시 여부와 공고의 행/카드 배치는 CSS가 결정하고, 실제 공고·신청·게시판 데이터와 로그인 권한은 공통 JS·서버가 처리합니다. 공고 보기 선택의 기본형은 각 시안에 맞게 표시되며 목록형은 사용자가 선택할 수 있습니다.

static/css/rms-home-design1.css 등의 파일은 퍼블리셔가 관리하는 시안 원본입니다. 내부 서비스에서 CSS 하나를 교체할 때는 위 themes/ 파일을 사용하세요. 기존 시연 도구에서 #home, #home/2, #home/3을 전환하는 방식은 퍼블리셔 비교용이며, 업무용 ZIP의 디자인은 rms-selected-design.css가 결정합니다.
